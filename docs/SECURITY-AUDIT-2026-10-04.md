# Аудит безопасности Passo — 2026-10-04

Вопросы владельца: (1) можно ли через сайт добраться до его GitHub; (2) можно ли
сломать что-то у других пользователей. Проверено на боевом сайте
(application-for-vercel.vercel.app), в коде репозитория и в истории git.

## Итог

| # | Вопрос | Ответ |
|---|---|---|
| 1 | Добраться до GitHub владельца через сайт | **Нет.** В сайте и истории нет ни одного токена или ключа; сайт не обращается ни к GitHub, ни к любому внешнему адресу (CSP `connect-src 'self'`). |
| 2 | Сломать данные других пользователей на хостинге | **Нет.** У сайта нет сервера и общей базы: прогресс каждого лежит только в его браузере. |
| 3 | Сломать данные тех, кто поставил десктопную версию (локальный сервер) | **Да, есть дыра V1** (средняя) и V2 (низкая). Исправление — задачи SEC1–SEC2. |

## Что проверено и в порядке

- **Боевой сайт отдаёт только публичное:** `/.git`, `/.env`, `/server`, `/docs`, `/scripts`,
  `/package.json`, `/vercel.json`, `/.github`, `/AGENTS.md`, `/legacy` — все 404. Доступны
  только страницы приложения и `data/*` (вопросы, уроки).
- **Заголовки:** строгий CSP (`script-src 'self'`, `connect-src 'self'`, `frame-ancestors 'none'`,
  `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`), HSTS (2 года, preload),
  `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`, COOP/CORP `same-origin`,
  запрет геолокации/камеры/микрофона. Единственная слабость — `style-src 'unsafe-inline'`
  (нужна, потому что интерфейс ставит `style=`; скрипты это не затрагивает).
- **Секреты:** рабочее дерево и вся история git чисты (`ghp_`, `github_pat_`, приватные ключи,
  `AKIA`, `api_key` — 0 совпадений). `.env`, `*.jks`, `keystore.properties` в `.gitignore`.
  Адрес `origin` больше не содержит токен.
- **XSS:** в `public/js` нет `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `eval`,
  `new Function`, `document.write`, `javascript:`; весь текст идёт текстовыми узлами через
  `el()` (это закреплено тестом). `mailto:` собирается через `encodeURIComponent`.
- **Зависимости:** ноль npm-пакетов, шрифты лежат в приложении (SIL OFL).
- **Файлы и пути:** `serveFile` отсекает выход из каталога (проверено `..%2f`, `%2e%2e`, 403/404);
  тело запроса ограничено 256 КБ (413), импорт — 8 МБ; запуск окна через `spawn` с массивом
  аргументов, без оболочки.
- **Service worker:** обрабатывает только свой origin, мутации идут напрямую в сеть.
- **GitHub:** репозиторий приватный (анонимный запрос к API даёт 404). CI без секретов и без
  `pull_request_target`.
- **Vercel:** защита превью выключена (ветка `self-improve` доступна по ссылке всем, кто её знает);
  секретов в превью нет, поэтому риск низкий.

## Найденное

### V1 — подделка запроса к локальному серверу (СРЕДНЯЯ, только десктопная версия)

Локальный сервер (`npm start` / установленное приложение, порт 3000) принимает изменяющие запросы
без проверки `Content-Type`, `Origin` и `Host`. Любой сайт, открытый в том же браузере, может
отправить «простой» кросс-сайтовый `POST` с `text/plain` (браузер не делает предварительный
запрос) на `/api/progress/import` и **перезаписать или обнулить прогресс**.

Доказано на пробном сервере: `POST /api/progress/import`, `Origin: https://evil.example`,
`Content-Type: text/plain` → `200`, имя профиля стало `HACKED`. `DELETE` защищён — браузер
требует предварительный запрос, а сервер отвечает 405 без заголовков CORS. Затрагивает только
тех, у кого приложение запущено на своём компьютере; на Vercel API нет.

### V2 — DNS rebinding (НИЗКАЯ, только десктопная версия)

Сервер не проверяет заголовок `Host`: запрос с `Host: evil.example:3980` вернул прогресс (200).
Сайт злоумышленника с коротким TTL DNS может читать и менять прогресс как «свой». Данные —
учебный прогресс, чувствительного нет.

### V3 — небезопасный поиск ключа в `answers` (НИЗКАЯ)

`recordAnswers` с id вида `constructor`, `toString`, `hasOwnProperty`, `valueOf` берёт
унаследованное свойство `Object`: у встроенных функций появляются поля (`Object.correct = NaN`),
а в прогрессе остаются «мусорные» ключи. Обычные объекты (`{}`) не затронуты, `__proto__`
отсекается. Из чужого сайта применимо только в связке с V1; в браузерной версии — только сам
пользователь через свой же файл.

### V4 — процесс и среда (СРЕДНЯЯ, организационная)

- Личный токен GitHub раньше был вписан в адрес `origin`. Такой адрес попадает в вывод команд,
  которые агенты читают и отправляют провайдеру модели (airouter.ch), и в мои логи. Адрес теперь
  чистый, но **токен нужно считать скомпрометированным: перевыпустить** как fine-grained токен
  только на этот репозиторий (Contents: read/write; Workflows — если нужен CI).
- В `ci.yml` нет блока `permissions` → права `GITHUB_TOKEN` зависят от настроек репозитория.
  Нужно `permissions: contents: read` (требует токена с правом `workflow`, см. SEC5).
- Установщики (`install.sh`/`install.ps1`) скачивают архив без проверки контрольной суммы, а
  однострочник в README ссылается на `raw.githubusercontent.com` приватного репозитория —
  у посторонних он не сработает (вопрос владельцу).
