# Как применять дизайн-систему в Patente Pro (для исполнителя)

Источник: дизайн-система владельца «Passo», выгружена 2026-09-29 из
claude.ai (артефакт U2zLPJLtuHSH8WPi4wgPxU). В этой папке — её копия для
чтения: `README.md` (бренд-бук), `tokens.json` (цвета/шрифты/отступы),
`guidelines/10-source-audit.md` (14 проблем текущего приложения и что с ними
делать), `components/<Имя>/README.md` (правила компонента),
`components/<Имя>/preview.html` (эталонная разметка), `components/bundle.css`
(эталонные стили всех компонентов, классы `ds-*`).

**Эта папка — справочник, а не код приложения.** Файлы отсюда НЕ подключать
к `public/` как есть; переносить нужное руками по задачам Спринта 2.

## Порядок чтения перед любой задачей Спринта 2

1. `README.md` — разделы Content fundamentals и Visual foundations.
2. `components/<компонент задачи>/README.md` + его `preview.html`.
3. Соответствующий блок `components/bundle.css` (ищи по комментарию `/* Имя */`).

## Где правила системы уступают правилам проекта (приоритет у проекта)

| Система говорит | В этом репозитории | Почему |
|---|---|---|
| `@import` Google Fonts (Onest, IBM Plex Mono) в bundle.css | **Внешние шрифты не подключать.** Onest и IBM Plex Mono уже лежат в `public/fonts/` (S2.13) — пользоваться `var(--font-sans)` / `var(--font-mono)` | CSP `'self'`, «nothing leaves the device», тест `the frontend never references an external origin` |
| `innerHTML` в `preview.html` (heatmap) | Только `el()` из `public/js/ui.js` | Жёсткое правило проекта, есть тест |
| Имя продукта «Passo» | **Принято 2026-09-29.** Видимое имя — Passo. Технические идентификаторы (`patente-pro` команда, папки прогресса `PatentePro`, пакет Android `app.patentepro.twa`, имя репозитория, формат бэкапа `app: 'patente-pro'`) НЕ менять | иначе пропадёт прогресс пользователей, Play сочтёт приложение новым |
| Feedback: «причина, называющая слово-ловушку» | Причину НЕ выдумывать. Использовать то, что уже есть в блоке WHY? (факты урока главы). Новые тексты объяснений не генерировать | Решение Фазы 1: explanation не заполняем (неточность недопустима) |
| «No shakes, bounces or confetti» | Встряску карточки при ошибке убрать (система права). Конфетти — **убрано** решением владельца 2026-09-29 | Конфликт системы и TODO — решает владелец |
| Все классы `ds-*` | Можно вводить классы `ds-*` в `public/styles.css`, но старые классы удалять только когда ни один экран их не использует (`grep -rn "имя-класса" public/`) | Экраны переводятся по одному, остальные не должны сломаться |

## Токены → CSS-переменные

Имена переменных = имена токенов (`--paper`, `--ink-muted`, `--accent-ink`,
`--ok-soft`, `--space-4`, `--shadow-sm`…). Светлая тема — в `:root`, тёмная —
в `[data-theme="dark"]` (так приложение уже переключает тему). Старые имена
(`--muted`, `--border`, `--shadow`, `--shadow-small`, `--font`) оставить как
алиасы на новые, пока их используют: `--muted: var(--ink-muted);`.

## Проверка каждой задачи

`scripts/verify.sh` (включая qa-new-user) + если к этому моменту есть
`scripts/qa-ux.mjs` — прогнать его и приложить сводку в DEVLOG. Контраст
текста ≥ 4.5:1 в ОБЕИХ темах — значения токенов уже подобраны под это, не
заменять их «на глаз».
