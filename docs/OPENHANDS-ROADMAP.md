## 1. Протокол исполнителя (обязателен в каждом запуске)

Модель исполнителя слабее архитектора — поэтому правила жёсткие и механические.

### 1.1 Цикл одного запуска

```
0. LOCK      блок ШАГ 0 из промта automation (lock по активности: чужой lock
             забирается после 15 мин тишины или 35 мин возраста). В конце — rmdir lock.
1. СИНХРОН   git status → если грязно (остатки упавшего запуска): git stash push -u
             -m "abandoned-run <дата>", строка об этом в DEVLOG, продолжать.
             git log --oneline -5 → не сделана ли задача уже (ищи ID задачи, напр. S1.3).
2. ВЫБОР     взять ПЕРВУЮ незакрытую задачу [ ] из раздела 2 этого файла.
             Задачи со значком 🔒 пропускать (см. 1.4 — несколько задач за запуск).
             Если первая незакрытая — ⛔ CHECKPOINT: СТОП, ничего не менять,
             ответ «CHECKPOINT: ждёт владельца», выход (строку ⛔ не отмечать).
3. ПЛАН      записать в начало ответа: файлы, шаги (≤5), команда проверки.
4. ШАГ       сделать один шаг → сразу проверить (команда из задачи).
5. ГЕЙТ      scripts/verify.sh  → должно быть "VERIFY OK". При правке public/ он сам
             прогоняет qa-new-user.mjs (~1 мин). Сценарий поднимает СВОЙ сервер
             на :3919 — никогда не запускай его с QA_URL на :3000.
6. КОММИТ    git add <конкретные файлы>; git commit -m "<тип>: <что> (S<N>.<M>)"
7. ДОКИ      отметить [x] задачу здесь + запись в docs/DEVLOG.md (сверху, по-русски)
             → verify → отдельный коммит "docs: ... (S<N>.<M>)".
8. ПУШ       git push origin self-improve (только эта ветка, без --force).
```

### 1.2 Откат и самодиагностика

- Проверка шага упала → **максимум 2 попытки исправить**. Каждая попытка:
  прочитать вывод ошибки целиком, назвать причину одной фразой, исправить.
- Третья неудача → `git restore .` и `git clean -fd` **только для файлов этой
  задачи** (сначала `git status`, посмотреть что удаляется), затем запись в
  DEVLOG:
  ```
  ## ВОПРОС: <дата> — <ID задачи> не выполнена
  Что пробовал: ... Ошибка (дословно, ≤10 строк): ... Гипотеза: ... Альтернатива: ...
  ```
  коммит только DEVLOG, конец запуска.
- Никогда не «чинить» тест, ослабляя проверку. Упал старый тест — виноват код.

### 1.3 Запреты (нарушение = откат)

- Не трогать: `data/questions/`, `legacy/`, `THIRD-PARTY-NOTICES.md`,
  `public/credits.html` (гейт проверяет).
- Не добавлять зависимости, CDN, внешние URL во фронтенд (CSP `'self'`).
- Не использовать `innerHTML`, `eval`, `new Function` — только `el()` из `ui.js`.
- JSON-данные не переписывать целиком «по памяти»: читать файл → менять
  объект в node-скрипте → писать обратно. Гейт ловит потерю записей overlay.
- Пушить только `self-improve` (обычный push); `main` не трогать, force-push и удаление веток запрещены.
- Не трогать задачи Фазы 2.1 (пауза) и всё, что помечено 🔒.
- Правка в `public/` → поднять `VERSION` в `public/sw.js` (+1).
- Не использовать API, которых нет в Node 18 (например, `node:sqlite`).
- Сервер для ручной проверки — только `PORT=3917 STORAGE_DIR=$(mktemp -d)`;
  порт 3000 может быть занят сервером владельца — его не убивать.

### 1.4 Бюджет

Несколько задач за запуск (решение владельца 2026-09-29): после пуша задачи —
если с начала запуска прошло < 22 мин, бери следующую; иначе завершай. Задачу,
которая явно не успеет до 28-й минуты, не начинать. Каждая задача — свои коммиты
и пуш сразу (не копить). Одна задача ≤ 20 минут и ≤ ~300 изменённых строк; если не
влезает — разбить на S<N>.<M>a/b прямо в этом файле, закоммитить разбиение,
выполнить первую. Читать на старте: раздел 1 этого файла + текст текущей задачи
(не весь файл).
